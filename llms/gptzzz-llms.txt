## 接入教程

- [Cursor 中转 API 配置：API Key、Base URL 与功能限制](https://gptzzz.ai/blog/cursor-api-relay/): Cursor 怎么接中转 API？在设置里填自定义 API Key 并开启 Override Base URL，先用 curl 预检网关，再逐项验证聊天、Agent、Tab 和流式。附三类 Key 的区别、常见报错和切回官方的方法。
- [Gemini API 中转接入：接口地址、API Key 与调用示例](https://gptzzz.ai/blog/gemini-api-relay/): 经 GPTZZZ 中转 Gemini API 走 OpenAI 兼容接口：Base URL 填 https://gptzzz.ai/v1，模型填 gemini-3.8-flash。另附 Google 原生与兼容接口地址、AI Studio 免费额度与 Key 获取、Gemini CLI 接中转的限制和报错排查。
- [Claude Code 中转站配置：API、Base URL 与验证](https://gptzzz.ai/blog/claude-code-api-relay/): Claude Code 怎么接中转 API？ANTHROPIC_BASE_URL 填网关根地址（不带 /v1），Key 用 ANTHROPIC_AUTH_TOKEN 或 ANTHROPIC_API_KEY，再验证模型、流式响应和工具调用，并检查密钥保护与切回官方的方法。
- [Codex 配置中转 API：CLI、VS Code、桌面 App 与换回官方配置](https://gptzzz.ai/blog/codex-cli-api-relay/): Codex 接中转 API：在 ~/.codex/config.toml 新增 Provider，base_url 填 https://gptzzz.ai/v1，env_key 写变量名，wire_api 用 responses。附 Windows/macOS 环境变量、VS Code 插件、桌面 App、CC Switch 与换回官方配置。
- [CC Switch 怎么配置中转站：Claude Code 与 Codex 一键切换](https://gptzzz.ai/blog/cc-switch-relay/): CC Switch 配中转站：Claude Code 请求地址填 https://gptzzz.ai（不带 /v1），Codex 填 https://gptzzz.ai/v1 并用 Responses。附安装、添加供应商、模型映射、切换生效、切回官方登录与常见报错。
- [DeepSeek API 中转接入：Base URL、模型名与调用示例](https://gptzzz.ai/blog/deepseek-api-relay/): DeepSeek 官方 Base URL 是 https://api.deepseek.com，经 GPTZZZ 中转填 https://gptzzz.ai/v1。附官方模型名 deepseek-flash、deepseek-v4-pro 与 GPTZZZ 模型 ID 对照、价格，以及 curl、Python 示例和 401/402/429 排查。
- [OpenAI 兼容 API 迁移：Responses、Base URL 与回滚](https://gptzzz.ai/blog/openai-compatible-api-migration/): OpenAI 兼容 API 怎么迁移？不只是换 Base URL：先对比 Responses 与 Chat Completions，冻结请求契约，再做影子验证、灰度切流和回滚演练，并处理好重试、密钥和日志脱敏。
- [OpenAI API 接入教程：Base URL 停在 /v1，每步有通过标准](https://gptzzz.ai/blog/openai-api-quickstart/): OpenAI API 怎么接入？Base URL 只写到 /v1，API Key 放进环境变量，先用一条 curl 跑通第一个请求，再换成 Python SDK 并验证流式输出。附 Responses API 基线、兼容接口的差异，以及 401、404、429 报错的处理方法。
- [Claude API 中转接入：Messages 请求与 Python 示例](https://gptzzz.ai/blog/claude-api-quickstart/): Claude API 中转怎么接？Base URL 只填主机根地址，路径固定为 /v1/messages，Key 放在请求头。附 curl 与 Python SDK 的第一条 Messages 请求、流式输出到 message_stop 的验证，以及 401、429、529 的处理。

- [API Key 安全：存储、权限、轮换与响应](https://gptzzz.ai/blog/api-key-security/): API Key 不该出现在前端、代码仓库和日志里。本文讲服务端存储、按项目拆分 Key、最小权限与日志脱敏，给出双 Key 无中断轮换和失败回滚的步骤，以及发现泄露后第一时间该做的撤销与排查。
